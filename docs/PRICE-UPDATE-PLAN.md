# 🔄 Сверхполный план обновления цен — Страховка.RS

> **Назначение:** инструкция для агента, который обновляет цены страховых полисов на сайте.
> Цель — найти **ВСЕ** места с ценами (их много и они дублируются), обновить каждое,
> синхронизировать источники/даты и проверить, что ничего не пропущено.
>
> **Главное правило:** одна и та же цена встречается в 5–7 разных местах файла. Если обновить
> только карточку компании, но забыть JS-объект `D` или калькулятор — на сайте будут
> противоречивые цифры. **Обновлять надо ВЕЗДЕ синхронно.**

---

## 0. Контекст проекта

- Сайт — один файл `index.html` (~909 строк), zero dependencies, vanilla CSS+JS.
- 6 компаний: **UNIQA, DDOR, Triglav, Wiener Städtische, Dunav, Generali**.
- Цены — в евро/год (€/год) или €/мес, иногда «По запросу» / «Калькулятор».
- Все данные помечены датой проверки (сейчас `26.03.2026`). При обновлении дату менять.
- Прошлый кейс обновления цены: [docs/solutions/2026-03-26-wiener-price-update.md](solutions/2026-03-26-wiener-price-update.md).

### Приоритет источников (от высшего к низшему)
1. **Официальный сайт / онлайн-калькулятор компании** (см. раздел 4) — главный источник.
2. Профильные агрегаторы (srb.guide и т.п.) — ориентир, если калькулятор недоступен.
3. Telegram-чаты / Trustpilot — только как «народный ориентир», помечать «из чата», НЕ как точную цену.

⚠️ Если официальный источник и чат расходятся — верить официальному, чат пометить как устаревший.

## 5. 🛠 Пошаговый порядок работы (для одной компании)

Повторить для каждой из 6 компаний:

1. **Проверить цену** в официальном источнике (раздел 4).
2. **Сравнить** со снимком (раздел 3). Если совпадает — отметить «актуально», идти дальше.
3. Если изменилась — **обновить во ВСЕХ зонах** (раздел 1) синхронно:
   - [ ] селектор таблицы (если цена в подписи опции)
   - [ ] карточка компании (`pkg-price` + тэглайн)
   - [ ] блок статистики/цитат (если упоминается)
   - [ ] калькулятор `recs.push(...price...)` — может быть **несколько** push с этой компанией
   - [ ] объект `D` (`price:` + сохранить/обновить сноску)
   - [ ] объект `TIPS` (текст подсказки про цену)
   - [ ] README таблица
4. **Проверить сноску** и ссылку источника (раздел 2).
5. Записать изменение в чек-лист (раздел 7).

⚠️ **Калькулятор — частая ловушка:** одна компания фигурирует в нескольких ветках
`if` (цена / стационар / бюджет / беременность). Найди ВСЕ `recs.push` с именем компании
(`grep -n "recs.push" index.html`) и обнови каждый.

## 8. 🔍 Контроль качества (перед коммитом)

1. **Поиск несоответствий** — одна цена не должна отличаться между зонами:
   ```
   grep -n "€" index.html | grep -i "wiener\|136\|11.39"   # пример для одной компании
   ```
   Для каждой компании убедиться, что во всех зонах одинаковая цифра.

2. **Открыть сайт** и проверить визуально:
   - таблица сравнения (переключить все селекторы → цены в строке «Цена/год» совпадают с карточками);
   - тултипы на ¹²³⁴⁵⁶ показывают корректный источник;
   - калькулятор (прогнать сценарии: цена/стационар/беременность) → рекомендации с верными ценами.
   (Использовать skill `/run` или Preview MCP для запуска.)

3. **Не осталось старых дат** «26.03.2026», если делалась полная перепроверка:
   ```
   grep -n "26.03.2026\|25.03.2026" index.html README.md
   ```

4. После проверки — записать решение в `docs/solutions/ГГГГ-ММ-ДД-<компания>-price-update.md`
   по образцу прошлого кейса (Problem / Root Cause / Solution / Prevention).

## 9. ⚠️ Типичные ошибки (не повторять)

- Обновил карточку, забыл объект `D` → таблица показывает старую цену.
- Обновил `D`, забыл `TIPS` → тултип противоречит ячейке.
- Обновил один `recs.push`, пропустил остальные ветки калькулятора.
- Поменял цену, но оставил старую сноску/источник → ссылка ведёт не туда.
- Выдумал точную цену там, где компания публикует только «По запросу».
- Забыл README — внешние читатели видят устаревшую сводку.
- Не обновил дату проверки → теряется доверие к «свежести» данных.
